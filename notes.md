When submitting a TypeScript project to GitHub, you should exclude the dist directory from your repository.
The dist (distribution) folder contains compiled JavaScript files generated automatically from your TypeScript source code. In Git version control, the best practice is to only track your raw source files, not the artifacts generated by building or compiling the code.
Here is a breakdown of what to include and what to exclude using a .gitignore file.

❌ What to Exclude (Add to .gitignore)
Create a file named .gitignore in your project's root directory and add these lines to prevent tracking generated or sensitive files:
• dist/ or build/ (Compiled JavaScript code)
• node_modules/ (Downloaded dependencies; others can install them via npm install)
• .env or *.env (Sensitive environment variables, API keys, and passwords)
• .DS_Store (Mac-specific system files)

What to Include
You should commit and push the following files to your GitHub repository:
• Source Files (/src): All your raw .ts or .tsx application files.
• Configuration Files:
    • package.json and package-lock.json (Defines your project dependencies and scripts).
    • tsconfig.json (Defines your TypeScript compiler configuration).
    • .gitignore (Tells Git what to ignore).
• Documentation: README.md (Explains how to install, build, and run your project).

Why exclude dist?
Redundancy: Anyone who clones your repository can generate the dist folder themselves by running your build script (e.g., npm run build).
Merge Conflicts: Generated files change entirely every time you compile. If multiple people work on the project, tracking dist will cause constant, messy code conflicts.
